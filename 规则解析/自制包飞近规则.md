# 自制包飞近规则

官机飞近在 `NoteConfigData.speed`（每颗 uid 1/2/3）。本机安装的 CustomAlbums **认通道 `0S` 值 `01/02/03`**（时间台阶，不是物件属性）。本仓库管线同样写 `0S` 多数档 + `chart.json` 同刻输家。不要用 `0O–0W` 表达飞近；那是画面流速（调色板仍叫「流速」）。不要为混速平移键位、不要叠两行 `0S` 指望分键。

编辑器另有单键钉死（飞近 1/2/3）和「无」（跟当时全局档）。

> 编辑器侧（近期策略，逐音符速度）：打开 MDM 时 `0S` 台阶**直接写回每颗可玩键的 `ApproachRate`**（不再生成一堆 `0X/0Y/0Z` 事件）；变速事件 `0X/0Y/0Z` 降级为**批量改档**标记——放置/拖动时把范围内的键盖成对应档；色带、事件列表、导出都按逐音符变化点派生。导出仍写 `0S` + 同刻输家 `chart.json`。

## 三档产物

| 档 | 谁认 | 写什么 |
|---|---|---|
| A 游玩包 | 本机 CustomAlbums | `info.json` + `map*.bms` + 媒体。飞近只有 `0S` |
| B 工程包 | 本编辑器 | A + `chart.json`。同刻输家回贴单键覆盖 |
| C 扩展包 | 要改播放器才认 | 另开字段。本仓库不写 |

## A：`0S` 台阶

1. 每个可玩键用当时档（钉死=覆盖档，「无」=已 stamp 的全局档）在该键时刻写档。
2. 相邻同档合并。长段按时间线上的 **192 槽**切开（同一槽只留一档）。
3. 同刻只留一档：先丢掉幽灵再多数票；平票取较小档。
4. 回到默认写 `0S:01`（收口），不要写编辑器 `0X`。
5. 后一颗「无」若档位与前一颗钉死不同，会在该键时刻换档，因此顺序不同速能进自制包，**不会**把后面的「无」钉死成前一颗的档。

同刻两颗不同速：输家不改 `0S`，少数派进 `chart.json`。写出的 zip 仍带 `chart.json`（CustomAlbums 忽略）。ChartLint **不报**同刻混速。

## B：`chart.json`

只存相对 `0S` 台阶仍不同的键（几乎只有同槽输家）。CustomAlbums 忽略该文件。编辑器按 **192 整数槽** + 通道 + ibms 贴回（时间戳已对齐拍子；旧包无 BPM 时才退回 20ms）。顺序钉死已进 `0S` 的，重开后显示「无」，有效档仍对。

## 摆锤 / 突击者：建议带飞近

摆锤 `0D`（倒 `0J`）、突击者 `0C`（倒 `0I`）自带高速出场动画。官谱里同元素连续出现时，受动画影响只能大致分辨落点（大约只能分辨 3/2 的落点）。

自制谱建议：带高速动画的摆锤 / 突击者**最好给飞近效果**，即在该键时刻写较高的 `0S`（档 3，至少高于局部基准档），让飞近和动画对上。按此导出的 MDM 与官谱基本一致。这是建议，不是硬规则。

官谱统计（游戏 bundle 扫全部 746 首）：

| 元素 | 总数 | ibms 拆分 | 档 1 / 2 / 3 |
|---|---|---|---|
| 摆锤 | 20300 | `0D` 20142 / `0J` 158 | 487 / 5199 / 14614 |
| 突击者 | 15790 | `0C` 15655 / `0I` 135 | 716 / 4876 / 10198 |

- 约 90% 与周围物件同档：它们多放在高速段，档 3 是跟着段落来的。
- 约 2–3% 比周围快：集中在 chrome_vox map4（76–84s）、milk map2/3、how_to_make_otoge_kyoku map4、mega_tskr map3、hana_to_yuki_to_drumn_bass map4。
- 也有档 1 或比周围慢的。所以档 3 常见但非必须。

实测出场时长（判定帧/30 s，档 1/2/3）：摆锤 26/21/18 帧（0.867/0.70/0.60 s），突击者 39/30/24 帧（1.30/1.00/0.80 s），普通键 44/38/33 帧。普通键速度比 1 : 1.158 : 1.333，不是 1 : 1.5 : 2。prefab、轨迹几何见 `mdm物件转化词典.md` §1.1–1.3。

## 同一拍不同速（特殊配置）

官谱允许同一 tick 上的物件飞近档不同，是有意为之，转录时保留。例：chrome_vox map4 在 76.317s、78.073s 等处，档 3 摆锤 / 突击者与档 2 物件同拍。全官谱同刻异速实例：摆锤 329、突击者 214。

处理（即上文 A 第 3 条 + B）：

1. `0S` 只是时间台阶，同刻只能留一档：幽灵让路，多数票胜，平票取较小档。少数派的档 BMS 表达不了。
2. 官谱转录：先检索整格设备延迟 D=`n×(240/BPM/192)`（BPM160 的 0.35 设置 → **45格=0.3515625s**，禁止直接减 0.35），再 `speed_transitions` / `speed_overrides`（192 槽）。通道 15 同一条轴。君往何处 map3 标准轴 `0S`：`0.75→3`、`78.375→1`、`78.75→3`、`141.375→1`。
3. 编辑器 `ApproachSpeed.ApplyOverrides` 会贴回；游戏内 CustomAlbums 忽略 `chart.json`，只吃 `0S` 多数档。编辑器打开/保存会把键和事件吸到 192 槽；Delay 只加减整格吃音，设备延迟不进 Delay 框。
4. 已验证：chrome_vox map1–4 共 143 个、umpopoff map2 共 49 个键，`0S` + `chart.json` 覆盖后与官谱完全一致。

手工做谱：要游戏内也显示，就别在同一拍放不同速；或把其中一颗错开极小时间，或接受多数档。
